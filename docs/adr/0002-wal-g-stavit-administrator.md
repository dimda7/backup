# WAL-G на хост БД ставит администратор, сервис только проверяет

Хосты БД работают на Astra Linux 1.8 и РЕД ОС 8.0 без выхода в интернет и без внутреннего репозитория, а готовых бинарников WAL-G под эти системы проект WAL-G не выпускает. Поэтому бинарник WAL-G — предварительное условие подключения: администратор сам кладёт его на каждый хост БД, а сервис не доставляет и не обновляет WAL-G, хотя канал до хоста у него есть и агент он ставит сам. Настройку WAL-G (конфигурация, хранилище, архивация WAL) по-прежнему делает сервис.

- **Бинарник.** Своя сборка из исходников под каждую ОС с libsodium, brotli и lzo, как в официальных выпусках. Рецепт сборки, фиксирующий версию и опции, входит в проект, чтобы на всех хостах БД стояла одна и та же сборка.
- **Путь.** Один фиксированный путь на всех хостах БД; агент и `archive_command` вызывают WAL-G только по абсолютному пути.
- **Версии.** Подходящими считаются только версии из точного списка, проверенного с данным выпуском сервера управления (текущая и предыдущая). Список и рецепт сборки обновляются вместе.
- **Проверка.** При первичном подключении сервис проверяет наличие и версию WAL-G и отказывается подключать хост БД, если проверка не прошла. Если версия стала неподходящей на уже подключённом хосте БД, сервис предупреждает и оповещает, но бэкапы и архивация продолжаются.
- **Обновление.** WAL-G обновляет администратор вручную на каждом хосте БД; сервис показывает, где версия отстаёт.

## Considered Options

- **Сервер управления разносит WAL-G сам** (администратор один раз загружает сборку под каждую ОС, сервис кладёт её на хосты вместе с агентом). Отклонён владельцем сервиса в пользу ручной установки, несмотря на ручную работу на каждом хосте при подключении и обновлении.
- **Официальные бинарники для Ubuntu** на Astra и РЕД ОС. Отклонён: их работа на этих системах не проверена, своя сборка даёт контроль над опциями.
- **Сторонние пакеты** (COPR и подобные). Отклонён: недоверенный источник для инструмента, читающего весь каталог данных.

## Consequences

- Подключение и обновление WAL-G требуют ручного шага на каждом из десятков хостов БД; автоматизировать его сервис не будет.
- Сервис проверяет версию, но не происхождение файла: на хосте БД может оказаться бинарник той же версии, собранный не по рецепту проекта.
- После обновления сервера управления часть хостов БД может оказаться с неподходящей версией WAL-G и продолжит работать с предупреждением, пока администратор не обновит их.

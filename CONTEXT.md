# Управление бэкапами PostgreSQL

Внутренний веб-сервис, который с отдельной машины настраивает, запускает и контролирует бэкапы PostgreSQL, выполняемые WAL-G на хостах БД.

## Language

**Сервер управления**:
Отдельная машина с веб-интерфейсом и API, с которой администратор управляет бэкапами всех хостов БД.
_Avoid_: обёртка, панель, контроллер, платформа

**Хост БД**:
Машина с одиночным экземпляром PostgreSQL, подключённая к серверу управления; политики бэкапа у неё может и не быть.
_Avoid_: нода, кластер, инстанс, сервер БД

**Агент**:
Компонент сервиса на хосте БД, который выполняет там операции по запросу сервера управления и отдаёт ему состояние хоста.
_Avoid_: демон, клиент, воркер, экспортёр

**Хранилище**:
S3-совместимый бакет (с необязательным базовым путём в нём), куда хосты БД кладут бэкапы и WAL; хост БД в каждый момент пишет ровно в одно хранилище.
_Avoid_: репозиторий, бакет, архив

**Линия бэкапов**:
Непрерывная история бэкапов и WAL одного хоста БД в одном месте одного хранилища; у хоста БД одна действующая линия и сколько угодно завершённых, доступных только для чтения.
_Avoid_: архив хоста, префикс (как имя понятия), цепочка

**Снятый с управления**:
Состояние хоста БД, у которого нет действующей линии бэкапов, но остались завершённые.
_Avoid_: удалённый, отключённый, архивный

**Политика бэкапа**:
Расписание полных бэкапов, необязательное расписание дельта-бэкапов и окно восстановления; принадлежит ровно одному хосту БД и ни с кем не разделяется.
_Avoid_: план, задание, расписание (как синоним всей политики), шаблон, стратегия

**Полный бэкап**:
Бэкап, для восстановления из которого не нужен никакой другой бэкап.

**Дельта-бэкап**:
Бэкап, содержащий только изменения с последнего полного бэкапа; для восстановления нужен он сам и этот полный.
_Avoid_: инкрементальный, дифференциальный

**Ручной бэкап**:
Полный или дельта-бэкап, запущенный администратором вне расписания; после создания ничем не отличается от бэкапа по расписанию.
_Avoid_: внеплановый, разовый

**Закреплённый бэкап**:
Бэкап, который администратор пометил как не подлежащий удалению по окну восстановления; вне окна из него можно восстановиться только на момент его окончания.
_Avoid_: постоянный, вечный, архивный

**Приостановленная политика**:
Политика бэкапа, по которой временно не запускаются бэкапы и не удаляются старые; архивация WAL при этом продолжается.
_Avoid_: отключённая, выключенная

**Окно восстановления**:
Число дней назад от текущего момента, на любой момент в пределах которых хост БД можно восстановить; единственное правило хранения бэкапов и WAL.
_Avoid_: срок хранения, глубина хранения, retention

**Наблюдатель**:
Роль пользователя, которому доступен только просмотр состояния бэкапов.

**Администратор**:
Роль пользователя, которому разрешено менять настройки и запускать операции на хостах БД, включая восстановление.

# Управление бэкапами PostgreSQL

Внутренний веб-сервис, который с отдельной машины настраивает, запускает и контролирует бэкапы PostgreSQL, выполняемые WAL-G на хостах БД.

## Language

**Сервер управления**:
Отдельная машина с веб-интерфейсом и API, с которой администратор управляет бэкапами всех хостов БД.
_Avoid_: обёртка, панель, контроллер, платформа

**Хост БД**:
Машина с одиночным экземпляром PostgreSQL, подключённая к серверу управления; политики бэкапа у неё может и не быть.
_Avoid_: нода, кластер, инстанс, сервер БД

**Агент**:
Компонент сервиса на хосте БД, который выполняет там операции по запросу сервера управления и отдаёт ему состояние хоста.
_Avoid_: демон, клиент, воркер, экспортёр

**Хранилище**:
S3-совместимый бакет (с необязательным базовым путём в нём), куда хосты БД кладут бэкапы и WAL; хост БД в каждый момент пишет ровно в одно хранилище.
_Avoid_: репозиторий, бакет, архив

**Линия бэкапов**:
Непрерывная история бэкапов и WAL одного хоста БД в одном месте одного хранилища; у хоста БД одна действующая линия и сколько угодно завершённых, доступных только для чтения.
_Avoid_: архив хоста, префикс (как имя понятия), цепочка

**Снятый с управления**:
Состояние хоста БД, у которого нет действующей линии бэкапов, но остались завершённые.
_Avoid_: удалённый, отключённый, архивный

**Политика бэкапа**:
Расписание полных и дельта-бэкапов вместе с правилами хранения для одного хоста БД.
_Avoid_: план, задание, расписание (как синоним всей политики)

**Наблюдатель**:
Роль пользователя, которому доступен только просмотр состояния бэкапов.

**Администратор**:
Роль пользователя, которому разрешено менять настройки и запускать операции на хостах БД, включая восстановление.
